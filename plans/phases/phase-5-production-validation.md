## المهام الفرعية

### M5.1 — اختيار ثلاثة فصول حقيقية
معيار الاختيار: **ثلاثة أنماط مختلفة جذريًا**
1. **نص كثيف** — فقرات طويلة، تداخل عميق، عناوين غير نمطية
2. **معادلات + جداول** — LaTeX كثيف، جداول طويلة/عريضة
3. **أكواد + لغة مختلطة** — كتل برمجية، عربي/إنجليزي في نفس المستند

> يمكن البدء من المشاريع الحالية، لكن يُفضَّل مادة جديدة من خارج ما صُمّم له المحرك.

### M5.2 — المسار الكامل لكل فصل
```bash
npm run washi -- new "..." --file <chapter>.md
npm run washi -- validate <id>
npm run washi -- render  <id> --out output/<id>
npm run washi -- publish <id> --yes
npm run washi -- verify  <id>
npm run washi -- trace   <id> --json
```
- **القبول:** صفر أخطاء هيكلية في الفصول الثلاثة.

### M5.3 — مراجعة PDF بصريًا
لكل فصل، فحص:
- [ ] تداخل الأقسام (nesting)
- [ ] الجداول الطويلة (هل تُقسَم أم تُقطَع؟)
- [ ] المعادلات الخاطئة (`merror`, قصّ SVG)
- [ ] المراجع المكسورة للصور
- [ ] اختلاف ترتيب العناوين
- [ ] خرائط المصدر (provenance)
- [ ] اختلاط اللغات والاتجاهات

- **القبول:** تقرير ملاحظات لكل فصل.

### M5.4 — تحويل الملاحظات إلى كود
كل ملاحظة تُصبح واحدًا من:
- **(أ)** قاعدة تحقق جديدة في `lib/validate.ts` (تحذير أو خطأ)، أو
- **(ب)** إصلاح في الرندرر / المحلّل

- **القبول:** كل ملاحظة مُغلقة بقاعدة أو إصلاح، لا شيء "مؤجل بلا أثر".

### M5.5 — التثبيت كـ fixtures
- نسخ الفصول الثلاثة إلى `tests/fixtures/`
- اختبارات golden في `tests/artifacts.test.mjs` تستهلكها
- **رفع `content/` من `.gitignore`** (أو نقل المادة إلى `tests/fixtures/`)
- **القبول:** `npm test` يعمل على الفصول الثلاثة.
