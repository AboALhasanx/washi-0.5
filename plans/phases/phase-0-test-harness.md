# المرحلة 0 — شبكة الاختبار (Test Harness)

**الأولوية:** P0 · **الحالة:** جارية · **تاريخ البدء:** 2026-09-10

---

## لماذا هذه المرحلة أولًا؟

التدقيق كشف أن المشروع **بلا إطار اختبار ولا CI إطلاقًا**:

- `package.json` لا يحتوي على سكربت `test`.
- لا يوجد `.github/` ولا أي مُشغّل (vitest / jest / node:test).
- الاختبارات الموجودة سكربتات يدوية متفرقة:
  - `scripts/cli-test.mjs` (132 سطر، 22 تحققًا)
  - `scripts/mcp-test.mjs` (102 سطر، 17 تحققًا)
  - `scripts/e2e-test.mjs` (288 سطر)
  - `scripts/ui-test.mjs` (373 سطر)
- لا شيء منها يعمل تلقائيًا، ولا شيء يُبلغ عن فشل برمز خروج موثوق.

**النتيجة:** لا يمكن تنفيذ M1 (توسيع المانيفست) ولا M3 (تفكيك `project.ts` /
إزالة الحالة العالمية من الرندرر) بأمان بدون شبكة أمان. لذلك M0 تسبق كل شيء.

---

## الهدف

```bash
npm test     # يمر بالكامل، exit 0 عند النجاح، exit 1 عند أي فشل
```

## المهام الفرعية

### M0.1 — مُشغّل الاختبارات
- **القرار:** `node:test` المدمج (Node 22 متوفر). **صفر تبعيات جديدة.**
- تعديل `package.json`:
  ```json
  "scripts": {
    "test": "node --test tests/",
    "test:watch": "node --test --watch tests/"
  }
  ```
- **القبول:** `npm test` يعمل ويخرج برمز صحيح.

### M0.2 — ترحيل اختبارات CLI
- **المصدر:** `scripts/cli-test.mjs` (22 تحققًا)
- **الهدف:** `tests/cli.test.mjs`
- التحويل من `check()` مخصّص إلى `node:test` + `node:assert`.
- الحفاظ على سلوك spawn الحقيقي: `execFileSync("node", [TSX, "cli/washi.ts", ...])`
  — لا shell، لتمرير الوسائط العربية بأمان.
- استخدام مشروع اختبار بمعرف ثابت لتجنّب تلويث `projects/`.
- **القبول:** 22/22 تحقق يمر عبر `node:test`.

### M0.3 — ترحيل اختبارات MCP
- **المصدر:** `scripts/mcp-test.mjs` (17 تحققًا)
- **الهدف:** `tests/mcp.test.mjs`
- الحفاظ على الاختبار عبر **البروتوكول الحقيقي** (stdio transport) لا استيراد مباشر.
- **القبول:** 17/17 يمر.

### M0.4 — Golden tests للـ artifacts
- **الهدف:** `tests/artifacts.test.mjs`
- إدخال: فصل Markdown ثابت → `tests/fixtures/`
- المخرجات المُختبَرة:
  - `buildDocumentAst()` — شكل الأقسام، معرّفات البلوكات (`s1`, `b1-1`)، `stats`
  - `buildAppContent()` — `concepts`, `flashcards`, `questionCandidates`, `stats`
- **القبول:** أي تغيير في شكل الخرج يفشل الاختبار فورًا.

### M0.5 — دورة النشر
- **الهدف:** `tests/lifecycle.test.mjs`
- السلسلة: `createProject → saveProject → publishProject → verifyPublication`
- الحالات:
  1. بعد النشر → `status: "ok"`
  2. بعد العبث بـ `content.md` → `status: "mismatch"` و`contentOk: false`
  3. حزمة غير موجودة → `status: "missing"`
  4. النشر بمستند غير صالح → `PublishError`
- **القبول:** الحالات الأربع تُمرّر.
- ⚠️ هذه الحالة (2) هي التي ستُثبت نجاح M1 لاحقًا.

### M0.6 — تنظيف مجلدات الخربشة
- ✅ **مُنجز مسبقًا** — `.gitignore` يحتوي بالفعل على:
  `/.e2e/`، `.uitest/`، `/output/`.
- تبقّى: ترحيل `scripts/e2e-test.mjs` + `scripts/ui-test.mjs` إلى `tests/ui/`
  (**مؤجل إلى M5** — يحتاجان متصفحًا ولا يصلحان كاختبارات وحدة سريعة).
